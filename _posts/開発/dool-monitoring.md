Laravelのスロークエリを調べていたときに、「アプリ側は遅くないのにサーバー全体が重い」というケースもありそうだと思い、サーバーのリソースをその場でリアルタイムに見る方法を調べました。`top` や `vtop` は知っていましたが、`dool` というコマンドを教えてもらったのでメモしておきます。

## doolとは

`dool` は、CPU・メモリ・ディスクI/O・ネットワーク・プロセスなどのシステムリソースを、**1つの画面に横並びでリアルタイム表示**してくれるコマンドラインツールです。

もともとは `dstat` というツールがあり、それがPython 2のサポート終了で開発が止まってしまったため、後継として作られたのが `dool` らしいです。使い方や見た目は `dstat` とほぼ同じなので、`dstat` を触ったことがある人ならそのまま移行できそうでした。

`top` との一番の違いは、**プロセス単位ではなく、システム全体の推移を時系列で見られる**点だと理解しています。「さっきからCPUが張り付いてる」「ディスクの書き込みが急に増えた」みたいな、時間の流れの中の変化を追いたいときに向いていそうです。

## インストール

Ubuntu/Debian系だとaptで入りました。

```bash
sudo apt update
sudo apt install dool
```

apt に無い場合は pip でも入れられるようです。

```bash
pip install dool
```

## 基本的な使い方

引数なしで実行すると、CPU・ディスクI/O・ネットワーク・ページング・システム（割り込み/コンテキストスイッチ）が1秒ごとに更新されます。

```bash
dool
```

```text
--total-cpu-usage-- -dsk/total- -net/total- --system--
usr sys idl wai stl| read  writ| recv  send| int   csw
 12   3  82   3   0|1024k  512k| 45k  120k| 980  1.2k
 45  10  38   7   0|3.5M  1.1M | 89k  210k|1.4k  2.0k
 78  15   4   3   0|8.2M  4.8M |210k  520k|3.1k  4.6k
```

数字が縦に流れていくので、`top` のような画面全体の書き換えに比べて**過去数秒〜数十秒の推移が一目で追える**のが便利だと感じました。

## よく使いそうなオプション

調べていて、実際に使いそうだったオプションをまとめておきます。

| オプション | 内容 |
|------------|------|
| `-c` | CPU使用率 |
| `-d` | ディスクI/O |
| `-n` | ネットワーク |
| `-m` | メモリ使用量 |
| `-g` | ページング |
| `-y` | システム（割り込み・コンテキストスイッチ） |
| `--top-cpu` | CPU使用率が高いプロセスを表示 |
| `--top-mem` | メモリ使用量が多いプロセスを表示 |
| `--top-io` | I/Oが多いプロセスを表示 |

必要なものだけ組み合わせて指定できるので、見たい観点だけに絞るとかなり見やすくなります。

```bash
# CPU・ディスク・ネットワーク・メモリだけを1秒間隔で表示
dool -cdnm 1
```

CPU負荷が高いプロセスを直接知りたいときは、こんな感じで指定しました。

```bash
dool -c --top-cpu 1
```

## CSVでログとして残す

`--output` オプションを使うと、表示している内容をCSVファイルにも同時に書き出せます。原因調査であとから振り返りたいときや、負荷試験の記録として残しておきたいときに便利そうでした。

```bash
dool -cdnm --output monitor.csv 1
```

出力されたCSVは表計算ソフトに読み込んでグラフ化すると、どのタイミングでリソースが跳ねたのかが分かりやすくなります。

## Laravelのスロークエリ調査と組み合わせる

前に書いた[スロークエリ・N+1検知の記事](/posts/laravel-slow-query-n-plus-one)と組み合わせると、こういう切り分けができそうだと思いました。

1. アプリ側のログ（`storage/logs/laravel.log`）で **どのクエリが遅かったか** の時刻を確認する
2. その時刻の `dool` のCSVログを見て、**同じタイミングでサーバー全体のCPUやディスクI/Oが跳ねていないか** を確認する
3. サーバー全体が重くなっていたなら「サーバーリソースの問題」、そうでなければ「クエリ自体・インデックスの問題」と切り分けられる

アプリのログだけでは「クエリが遅かった」ことしか分からないので、サーバー側のリソース状況を並べて見られると原因の当たりを付けやすくなりそうです。

## まとめ：doolでできること

- `dool` はCPU・メモリ・ディスクI/O・ネットワークなどを**1画面でリアルタイムに横並び表示**できるツールで、`dstat` の後継にあたる
- `top` がプロセス単位の瞬間値を見るのに向いているのに対し、`dool` は**システム全体の時系列の推移**を追うのに向いていそう
- `-c` `-d` `-n` `-m` などのオプションを組み合わせて、見たい項目だけに絞って表示できる
- `--output` でCSVに書き出せるので、後から振り返る調査ログとしても使える
- アプリ側のログ（スロークエリなど）と時刻を突き合わせると、「アプリの問題」か「サーバーリソースの問題」かを切り分けやすくなる

今まで負荷が高いときは `top` を見るだけで済ませていましたが、`dool` を知ってからは推移をまとめて追えるようになって、原因調査がだいぶやりやすくなった気がします。
